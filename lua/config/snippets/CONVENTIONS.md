# Snippets 编写约定

## 职责与依赖

- `lua/snippets/` 是 LuaSnip 装载入口，只选集合、设置命名空间并返回普通／自动两张表。
- `core/` 提供通用构造、节点、匹配、条件、作用域和生命周期机制，不导入语言功能。
- `shared/rules/` 保存 Greek、alias、decoration、script 的语义规则，不导入 LuaSnip 或功能实现；`shared/` 只放有实际跨语言调用方的编辑策略／构造。
- 数学的 `latex/math/syntax.lua` 与 `typst/math/syntax.lua` 各自解释 token、参数和脚标；返回无损原文结构，不访问 buffer。语法知识不能通过通用 syntax 开关表拼装。
- `shared/math_postfix` 统一数学后缀的 reader 调用、失败处理和原文消费范围；操作回调只返回 captures。`whole` 明确处理完整操作数的范围括号，普通 `engine` 不隐含编辑策略。工厂继续负责规则、条件和新节点。
- `shared/math_snippets` 按明确编辑操作构造脚标、装饰、分数入口（固定上标仍有命名私有操作），统一 captures／新节点及注册契约；语言功能保留原生模板、渲染与条件。它不解释语法，不用 action 分派或语言开关装配解析器。
- `decorations` 处理基底装饰，`wrappers` 处理完整表达式／显式定界操作。后缀包装／分数把一层完整圆括号作为范围标记去掉；双层保留一层。脚标绑定、显式定界符替换与函数参数语法分别处理，不能无条件剥括号。失败返回 nil，不从未知结构中猜测消费范围。
- `latex/`、`typst/`、`markdown/` 按功能组织。普通与自动入口、专用匹配器和节点尽量就近维护；只有真实的多个调用方才抽出共享模块。
- 同一语言的多个入口若共享输出，可在功能文件内复用原生格式模板；trigger、类型、优先级及特殊节点仍显式保留，不引入节点配置 DSL。
- 功能模块提供 `snippets()`、`autosnippets()` 中实际存在的函数。每次调用创建新节点，不缓存 snippet 对象，不写空工厂凑接口。规则已声明 `snippetType` 时可一次构造混合类型定义，由 LuaSnip 注册路由，不必再次按普通／自动过滤；调整返回列表时需验证同优先级候选顺序。
- 连续输入的 boundary 在规则调用处显式指定；省略始终表示不设前字节阻挡，不使用语言不同的默认值或 false 哨兵。
- 集合开关在构造前判断，默认启用。不以历史来源或使用频率划分目录。

## 文件顺序与排版

普通模块顺序：职责说明 → `local M` → 外部依赖 → 项目依赖 → LuaSnip 节点别名 → 项目辅助函数别名 → 类型／常量／规则 → 私有函数 → 导出函数 → `return M`。

纯规则文件可以直接返回表；装载入口不必创建 `M`。紧邻接口的类型说明可以放在该接口前。私有闭包留在使用处，避免为了排序扩大作用域。

使用仓库 StyLua 配置。函数内部按输入准备、边界判断、主体处理、结果生成等实际阶段留一行；连续简单语句和同组常量保持紧凑。snippet 定义按主题分段，不逐条添加空行，也不为了压行合并无关操作。

LuaSnip context 字段顺序为 `trig`、`name/dscr`、`trigEngine/wordTrig`、`priority/snippetType`、其余选项。短表保持单行，长表由格式器排版。

## 引入与命名

LuaSnip 使用固定别名 `s/sn/isn/t/i/f/d/c`，extras 使用 `fmt/fmta/rep`。项目函数使用完整语义的本地别名；相同函数不混用别名和模块限定调用。条件对象、规则数据仍使用 `conditions.math` 等命名空间访问。

依赖默认集中在顶部。根据集合开关加载功能，以及跨插件懒加载／热重载范围的依赖，可以在使用时引入。长期存活的 `plugins/snippets.lua` 不得缓存会被清理的 `config.snippets.*` 对象；移动状态模块时同步更新其清理入口。

`name` 描述操作语义；语言输出不同不意味着名称不同。仅语义或操作方式不同才加覆盖名称，postfix、自动入口等区别保留。`dscr` 用于额外说明，不将规则的展示名称误叫 description。

## 契约与类型

显而易见的集合工厂不需要套话注释。有契约的接口说明 captures 顺序、返回对象、缺省／失败行为、是否修改输入、字节／显示列单位及生命周期约束。

节点工厂直接返回节点；返回回调的接口必须明确标识。完整 snippet 使用 `LuaSnip.Snippet`，普通节点使用 `LuaSnip.Node`。项目类型只描述项目概念或插件未完整声明的回调字段，不重复创建插件已有空类型。

`utils.extend(defaults, overrides)` 返回新表，浅合并且后者覆盖前者。不要用它替换需要深合并的配置，也不添加单纯转发已有工具的通用 utils。

## 验证

结构调整核对注册定义的 trigger、匹配选项、优先级与展开预览；名称和有意改变的行为另行核对。涉及 captures、选区、空格或重载时使用真实输入测试，包含光标、撤销、嵌套与取消路径。格式和 LuaLS 通过不能代替职责与可读性审查。
